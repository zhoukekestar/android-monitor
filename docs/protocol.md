# Android Monitor Phase 0 Protocol

Phase 0 uses one TCP connection over USB-reversed localhost.

Default port:

```sh
adb reverse tcp:38888 tcp:38888
```

The Mac host listens on `127.0.0.1:38888`. The Android receiver connects to
`127.0.0.1:38888` from the device, which ADB routes back to the Mac.

Status Panel mode uses a separate USB-reversed localhost TCP connection:

```sh
adb reverse tcp:38889 tcp:38889
```

The status-panel server listens on port `38889`, and Android connects to the
same port when the receiver is switched to Status Panel mode.

## Connection Start

After TCP connect, Android sends one UTF-8 JSON line terminated by `\n`:

```json
{"type":"client_hello","manufacturer":"Xiaomi","model":"Redmi Note 3","api_level":21,"screen_width":1920,"screen_height":1080,"supported_codecs":["h264"]}
```

Required values:

- `type`: `client_hello`
- `manufacturer`: Android device manufacturer
- `model`: Android device model
- `api_level`: Android SDK/API level
- `screen_width`: receiver screen width in pixels
- `screen_height`: receiver screen height in pixels
- `supported_codecs`: currently includes `h264`

The Mac sends one UTF-8 JSON line terminated by `\n`:

```json
{"type":"stream_config","codec":"h264","format":"annexb","width":1024,"height":600,"fps":15,"bitrate_mbps":2}
```

Required values:

- `type`: `stream_config`
- `codec`: `h264`
- `format`: `annexb`
- `width`: encoded frame width
- `height`: encoded frame height
- `fps`: nominal frame rate
- `bitrate_mbps`: configured encoder bitrate in megabits per second

## Stats

During streaming, Android sends periodic UTF-8 JSON lines back to Mac:

```json
{"type":"stats","decoded_frames":120,"dropped_frames":0,"input_fps":15.0,"bitrate_mbps":2.1}
```

Required values:

- `type`: `stats`
- `decoded_frames`: total output frames released by `MediaCodec`
- `dropped_frames`: frames dropped before input to `MediaCodec`
- `input_fps`: incoming video packet rate over the last stats window
- `bitrate_mbps`: incoming stream bitrate over the last stats window

MacHost may use these stats to lower the encoder bitrate when decoder pressure
is sustained. The stream configuration line remains the initial target; the
Android overlay reports measured incoming bitrate from stats.

## Errors

If the receiver hits a readable stream or decoder setup failure while the socket
is still open, Android sends a UTF-8 JSON line back to Mac before retrying:

```json
{"type":"error","message":"Unsupported stream: hevc/annexb"}
```

Required values:

- `type`: `error`
- `message`: readable failure detail

## Touch Input

When touch input is enabled on Android, the receiver sends normalized touch
events as UTF-8 JSON lines back to Mac:

```json
{"type":"touch","action":"down","x":0.42,"y":0.35}
```

Two-finger scroll gestures use the same message type:

```json
{"type":"touch","action":"scroll","x":0.42,"y":0.35,"delta_x":0.0,"delta_y":-0.08}
```

Required values:

- `type`: `touch`
- `action`: one of `down`, `move`, `up`, `cancel`, or `scroll`
- `x`: horizontal coordinate normalized to `0.0...1.0`
- `y`: vertical coordinate normalized to `0.0...1.0`
- `delta_x`: for `scroll`, horizontal movement normalized to receiver width
- `delta_y`: for `scroll`, vertical movement normalized to receiver height

MacHost maps normalized coordinates to the current virtual display bounds and
posts left-mouse events or pixel scroll-wheel events. On macOS this may require
Accessibility permission for the terminal or app launching MacHost.

## Video Packets

After the JSON line, every video packet is binary:

| Offset | Size | Field |
| --- | ---: | --- |
| 0 | 4 | Magic `0x414D4F4E` (`AMON`) |
| 4 | 1 | Version, currently `1` |
| 5 | 1 | Packet type, `2` for video |
| 6 | 2 | Flags, bit `0` means keyframe |
| 8 | 4 | Sequence number |
| 12 | 8 | Presentation timestamp in nanoseconds |
| 20 | 4 | Payload length in bytes |
| 24 | N | H.264 Annex-B payload |

All integer fields are big-endian.

H.264 keyframes include SPS/PPS NAL units before the IDR frame. The Android API
21 receiver waits for a packet containing SPS, PPS, and IDR before feeding
Annex-B payloads directly into `MediaCodec` with MIME type `video/avc`.

## Status Panel Snapshots

Status Panel mode is line-oriented UTF-8 JSON only. After Android connects to
port `38889`, the Mac sends a snapshot about every two seconds:

```json
{"type":"status_snapshot","host":"Mac","timestamp":"2026-05-05T06:35:16Z","uptime_seconds":142607,"command_output":"...","build_status":"...","cpu":"...","memory":"...","disk":"...","network":"...","log_tail":"..."}
```

Required values:

- `type`: `status_snapshot`
- `host`: readable host name
- `timestamp`: ISO-8601 timestamp generated by the Mac
- `uptime_seconds`: Mac uptime from `ProcessInfo`
- `command_output`: compact terminal/status command output
- `build_status`: presence checks for built Mac and Android artifacts
- `cpu`: compact top-CPU process list
- `memory`: compact memory statistics
- `disk`: root filesystem capacity
- `network`: primary interface state
- `log_tail`: recent Android Monitor host log tail when available

Status Panel mode does not create a virtual display and does not use the video
packet stream.
